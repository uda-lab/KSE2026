\section{Engineering Implications and Limitations}\label{sec:discussion}

\subsection{Implications for AI in mathematics}

The principal design question is which artifact each control can assess.
The observed cases support the following recommendations for projects in
which agents develop a substantial formalization under a mathematical
owner. They do not establish the causal effectiveness of the harness.
% CLAIM: CLM-005, CLM-009

\emph{Keep mathematical authority outside the implementation role.}
Elaboration establishes that a proposition is well formed, not that it
expresses the intended mathematics. The scientific owner should approve a
statement contract before implementation when the scope is delicate, and
a reviewer who did not write the proof should test its hypotheses and
boundary cases. Cases A and B show the different outcomes when this review
occurs during release preparation or before merge.
% CLAIM: CLM-005, INC-001, INC-002

\emph{Use the GitHub workflow to route mathematical feedback.}
The repository's \texttt{github-driven-workflow} gave each approved Issue
one branch, one Git worktree owner, and one PR record. Its mathematical
value came from routing semantic findings to the owner and statement
contract, while returning implementation findings to the worktree. The PR
then preserved the candidate, the applicable checks, and the decision in
one durable record. % CLAIM: CLM-007, CLM-009, EV-2076, EV-1669

\emph{Separate observation from modification.}
A scout inspected repository assumptions without edit permission, and
specialist reviewers examined mathematical scope, module structure, or
the public declaration inventory. These roles received only the authority
needed for their task. The declaration comparison in PR~\#120 found a
missing theorem after both the build and a structural review had passed.
% CLAIM: CLM-007, CLM-008, CLM-009, INC-004

\emph{Place resource rules in the dispatch path.}
In the VPS container, exclusive Git worktree ownership, cleanup of helper
processes, cache reuse, a global build lock, and available memory checks
were prerequisites for verification. Recording an incident in an agent's
memory was insufficient because later agents and tools could change. The
resource contract was therefore placed in standing instructions and
repeated in each relevant dispatch. % CLAIM: CLM-007, CLM-008, CLM-009, INC-005

\subsection{Evidence and limits}

The study concerns one project under one scientific owner. Six sessions
were chosen for incident reconstruction, so their coded events cannot
estimate failure prevalence or the effectiveness of a control. There is
no matched project without agent orchestration, and the observations do
not identify causal effects. % CLAIM: CLM-004, CLM-005

The session record has gaps, including early records lost to log
retention. Reconstructed events are distinguished from primary session
evidence and carry an explicit confidence assessment. The models and
proprietary tools also changed outside the project's control, which limits
behavioral reproducibility. The recommendations are therefore expressed
through artifacts, responsibilities, and observable checks rather than a
requirement to use the same software. % CLAIM: CLM-008, INC-003

The Issue and pull request writes that reached GitHub through ChatGPT's
Connector came from the owner's authenticated account, and the project's
recorded authorship policy treats them as owner decisions regardless of who
drafted their text. That authority follows from the account and the policy
rather than from a record of approval for each write. A lexical search of the
exported ChatGPT conversations found an earlier instruction naming the same
repository before 54 of these 174 writes, while 27 had no earlier instruction
and 89 could not be traced to a single originating message. Inspection also
rejected 4 further candidates whose preceding message had deferred the action
rather than requested it. The signal is reconstructed from visible conversation
text with medium confidence, and an earlier instruction in the conversation does
not establish that the owner approved that particular write in advance.
% CLAIM: CLM-012, CLM-013

The owner's supervision was part of the harness and cannot be separated
from its outcome. Section~\ref{sec:formalization} bounds the mathematical
result to the unforced equations, an arbitrary
fixed finite horizon, test functions separated in time and space, and the
stated energy class. The paper makes no claim about uniqueness or higher
regularity.

Redacted evidence excerpts, claim-to-evidence manifests, and scripts for
the reported metrics are available in the paper repository. Raw session
logs are withheld to protect the people and systems recorded in them.
