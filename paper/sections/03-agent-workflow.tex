Over the six-week campaign (2026-06-10 through the release day 2026-07-20)
the project ran as long-lived orchestrating sessions, each directing a
changing population of delegated sub-agents. Measured only over sessions
in the evidence store (a documented lower bound; a June logging gap and
other coverage gaps remain, \S\ref{sec:discussion}), it consumed at least
15.1M output tokens, an API-equivalent cost of \$6{,}973, and 199.1h of
active engagement time under a 5-minute inter-event gap cap. % CLAIM: CLM-002
This section reconstructs the workflow from six sessions independently
event-coded against a fixed vocabulary (Table~\ref{tab:event-codes}) -- a
purposive sample chosen for reconstruction value, not a random or
exhaustive one. % CLAIM: CLM-004

\subsection{Role separation and delegation}

From the earliest surviving session (2026-06-15--06-20) the orchestrator
was already constrained to a single rule: it does not edit
target-language files itself; every change is dispatched through a
sub-agent call. There, a single orchestrator issued 107 dispatches
across three roles -- 47 coder, 45 prover, 12 planning -- plus 3
exploration calls. % CLAIM: CLM-007, EV-2076 (session 74aab39b)
The same separation held later, when 152 dispatches were checked against
an adjudicator independent of the orchestrator's own judgment. % CLAIM: CLM-007, EV-0925 (session 90fa24bb)
By the refactoring campaign the role set had differentiated into five:
an orchestrator/architect; a documentation coder; an implementation
coder carrying issues end-to-end; a read-only scout checking assumptions
before implementation starts; and two independent reviewers in
parallel, one auditing module layering, the other doing exhaustive
per-declaration comparison via one spawned sub-agent per pull request --
pre-correcting eight issue/code mismatches before implementation began.
% EV-1669 (session 7e6156bf)

\subsection{Statement freeze, independent verification, and adversarial review}

A merged declaration's type is treated as frozen: a later pull request
may extend a proof but not narrow, delete, or silently generalize it
without that surfacing at review. An adjudicator, structurally separate
from the implementing coder, inspects each candidate statement before
merge: it rejected an over-strong, hypothesis-free derivative-continuity
lemma, and later found a \texttt{sorry} under a proposition false for
unconstrained inputs, settled by a numeric counterexample (a
magnitude-80 discrepancy) against a near-zero residual. A byte-diff
reviewer separately caught an unannounced deletion of a public theorem
inside a large refactor, restored as a thin wrapper before merge.
% EV-0925, EV-1669, leray-hopf\#20, leray-hopf\#27, leray-hopf\#120
These catches contrast with one release-blocking postmortem case
(\S\ref{sec:incidents}) where a declaration's type never faced this
scrutiny: an earlier campaign against it ended with a ``consumer''
verdict -- nothing downstream referenced it -- not a soundness verdict,
and the false generalization was caught only later. This is a contrast
in review coverage, not a claim independent review would necessarily
have caught the defect earlier. % INC-001, EV-0925

An adversarial review pass, run at high effort against every pull
request as a final gate, sits atop the adjudicator and byte-diff
reviewer; it once caught a sub-agent's own incorrect unsoundness claim.
Its plumbing needed iteration: the merge monitor initially watched only
formal review events and missed one delivered as a top-level comment,
stalling a merge until the supervisor caught the discrepancy; it was
rewritten to watch three channels at once, with no repeat across the
ten pull requests that followed, and the review tool was once found
pinned to an unavailable model identifier, failing every call until
corrected. % EV-1669, EV-0925, EV-2076

\subsection{Model escalation, worktree conflicts, and resource-aware orchestration}

Orchestrator model choice changed over the campaign: an opus-class model
drove the earliest sessions, while later the orchestrator ran a newer
general-purpose model with teammates on a lighter one; escalation was
considered repeatedly but never exercised, and assignment was role-typed
(104 of 107 earliest-session dispatches used a long-context
heavier-model variant for proof work, exploration the lightest). A
safety classifier once hard-blocked a repository push even after the
supervisor had approved it in conversation; the supervisor completed it
from a terminal, friction not resolved by any escalation path available
to the agent. % EV-1669, EV-2076

Parallel dispatch across worktrees became the default shape from the
axiom-removal campaign onward, rising to multiple independently named
agents each owning a worktree concurrently. Some conflicts were
designed out pre-emptively (a shared import file restricted to one
coder); others surfaced live: a reviewer re-verified a diff after
detecting concurrent editing mid-review, and a stale-liveness
misjudgment dispatched a second agent onto a worktree a first, still-live
agent already owned, until noticed and stopped. % EV-0925, EV-2076, EV-1669, EV-0247

Resource management is treated only briefly here; the incident that
forced it into standing rules -- a memory-exhaustion cascade traced to
accumulated helper-process chains, not the Lean build -- is analyzed in
\S\ref{sec:incidents}. The rules now in force (a global build lock, a
shared build cache, a pre-build memory check, mandatory helper-process
cleanup) did not exist earlier; they are a direct, incident-triggered
addition. % EV-0247

\subsection{Evolution across the campaign}

Table~\ref{tab:event-codes} is not a census of the full campaign, only
the sampled sessions. % CLM-004
Almost every standing rule above traces to a specific, dated failure
rather than upfront design: statement-freeze hardened after the
earliest WEAKEN catches; the review monitor followed one missed
comment; the resource rules followed the memory-exhaustion cascade. The
one discipline from the earliest coded session is commit-time
re-verification of on-disk state before trusting a sub-agent's reported
progress, adopted after repeated process deaths (network and
idle-timeout failures) left partially written files behind, every one
caught and reverted before commit. % EV-2076
This alone does not explain the zero \texttt{FALSE-SUCCESS} count --
later sessions layer independent review atop it -- but it is the one
mechanism common to all six, and none records a false success reaching
a merge.
