\section{Incidents and Recovery}\label{sec:incidents}

A successful Lean build establishes that the declarations in the checked
dependency graph are well typed. It does not determine whether a theorem
states the intended mathematics, whether a refactor preserved every public
declaration, or whether the runtime can complete the next build. The four
cases below concern these distinct boundaries. % CLAIM: CLM-008

The evidence combines repository records with six agent sessions selected
for their reconstruction value. The sample is neither random nor
exhaustive, so the cases document observed failures and recoveries without
estimating failure rates or causal effects. % CLAIM: CLM-004, CLM-008

All PR numbers in this paper refer to the leray-hopf
repository~\cite{lerayhopf2026repo}.

\subsection{Statement correctness}\label{sec:inc001}

\emph{Case A. A false generalization detected before release.}
A public continuity lemma accepted arbitrary exponents \(p,q\geq 1\),
although the mathematical argument used \(p=q=2\) and
Cauchy--Schwarz. The declaration carried an explicit \texttt{sorry}, and
a later proof attempt checked only that no capstone theorem depended on
it. The false general statement remained public for about a month and was
also repeated in project documentation. The capstone theorems were
unaffected. % CLAIM: CLM-008, INC-001

\emph{Detection and response.}
During release preparation, a statement reviewer tested the boundary case
\(p=q=1\). A weighted Hilbert triple and spike sequence satisfied the
stated integrability assumptions but admitted no almost everywhere
equivalent representative that was continuous in the intermediate Hilbert space. The
problem was therefore the proposition, not a difficult proof. The repair
restricted the declaration to \(p=q=2\) and moved it outside the public
imports in PR~\#162. PR~\#170 added a statement card and regression checks
for both the unsupported signature and a placeholder without a card.
% CLAIM: CLM-008, INC-001

\emph{Lesson.}
A placeholder records that a proof is absent. It provides no evidence that
the proposition is true. A public statement should be reviewed before
proof search, especially when its quantifiers or exponents exceed those
used in the motivating argument. Two days after PR~\#170 introduced the
independent review rule, PR~\#177 merged a documentation correction with
no requested or submitted review. The rule was not yet operationally
reliable. % CLAIM: CLM-008, INC-001

\emph{Case B. A missing hypothesis found before merge.}
A second placeholder asserted antisymmetry for a finite Fourier
truncation but omitted the hypotheses that keep both arguments inside the
finite projection space. Two proof revisions had attempted this
unrestricted statement before an independent reviewer identified the
missing closure condition. % CLAIM: CLM-008, INC-002

\emph{Detection and response.}
The reviewer tested inputs outside the intended subspace. A numerical
diagnostic produced a discrepancy of approximately \(80.7\) without the
projection hypotheses and approximately \(10^{-13}\) after imposing them.
These values corroborated the structural diagnosis. They were not a
certified counterexample. PR~\#27 added the two projection invariance
hypotheses, completed the Lean proof, and removed the placeholder before
merge. % CLAIM: CLM-008, INC-002

\emph{Lesson.}
For identities derived from truncation or projection, review should test
inputs outside the invariant subspace. Case B shows a defect caught by
that review, whereas the analogous review occurred much later in Case A.
The pair is informative but is not a controlled comparison.
% CLAIM: CLM-005, CLM-008, INC-001, INC-002

\subsection{Public declarations during refactoring}

PR~\#120 replaced duplicate proofs in two files with instances of a shared
module. The refactored code built successfully, but one unreferenced
public theorem had disappeared. No downstream dependency failed, so the
Lean build and an earlier review of module structure did not reveal the
omission. % CLAIM: CLM-008, INC-004

\emph{Detection and response.}
A separate reviewer compared the public declaration inventory before and
after the refactor. The missing theorem was restored as a thin wrapper
around the shared implementation, and the reviewer repeated the
comparison before merge. % CLAIM: CLM-008, INC-004

\emph{Lesson.}
When a refactor promises interface preservation, the review target must be
the complete public declaration set, including declarations with no
current users. A build tests dependencies. An inventory comparison tests
preservation. % CLAIM: CLM-008, INC-004

\subsection{Resource availability and orchestration}\label{sec:inc005}

The VPS container had an effective memory limit of 3.42\,GiB and no swap.
Review jobs from the previous night left fourteen helper process chains
running after their Git worktrees were inactive, consuming about
1--1.5\,GiB. At the same time, the orchestrator misclassified a slow agent
as inactive and assigned a replacement to the same Git worktree. The
replacement did not receive the shared cache rule and started a full
mathlib build. Under the combined load, Lean builds repeatedly ended with
exit code 137 and no compiler diagnostic. % CLAIM: CLM-008, INC-005

\emph{Detection and response.}
Monitoring had covered the visible Lean process rather than memory
available to the entire container. Roughly seventy minutes after an earlier
status check had produced that misreading, the author requested another when
only 606\,MiB remained available. Inspection of each process working
directory identified the fourteen stale chains, and the Linux control
group counter confirmed intervention by the out of memory (OOM) killer.
Because that counter was cumulative, it identifies the mechanism but not
the number of kills in this incident. Removing the stale processes raised
available memory to 2.2\,GiB. The worktree returned to the original agent,
the duplicate stopped, and the build completed under a global lock.
PRs~\#174, \#175, and \#176 merged later that day. % CLAIM: CLM-008, INC-005

\emph{Lesson.}
An orchestrator must observe the complete process tree and available
memory, not only the foreground prover. The standing instructions now
require cleanup of helper processes, reuse of the build cache,
serialization of heavy builds, and a memory check before compilation.
Monitoring available memory also detected a later peak caused by one
legitimate build, showing why a direct measurement of the resource is more
general than cleanup tailored to one cause. % CLAIM: CLM-008, INC-005
