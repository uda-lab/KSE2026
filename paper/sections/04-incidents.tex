\section{Incidents and Recovery}\label{sec:incidents}

% Scope (PLAN.md §7.4): representative examples from mathematical-meaning errors,
% false success reports, resource exhaustion, orchestration failures.
% Each incident presented here must have a card evidence/incidents/INC-NNN.md
% with confidence-of-reconstruction stated. Reference as: % CLAIM: INC-NNN

A successful build establishes that Lean accepts the declarations in
the checked dependency graph, and an axiom check records the assumptions
on which a selected result depends. Statement review assesses mathematical
scope, declaration comparison preserves the public interface, and resource
checks protect execution. We examine four incidents at these three
boundaries. % CLAIM: CLM-008

The evidence combines incident records with a purposive sample of six
agent sessions selected to cover distinct phases of the campaign.
The sample was neither random nor exhaustive.  The cases therefore
document observed failures and recoveries; they do not estimate failure
rates or the causal effect of the guardrails. % CLAIM: CLM-004, CLM-008

\subsection{Statement correctness: two contrasting cases}\label{sec:inc001}

\paragraph{Case A: a false generalization detected before release.}
\emph{Invariant at risk.}
The scope of a public statement must not exceed the scope supported by
the mathematical argument, even while its proof remains a placeholder.
In this case, the argument under consideration used the Hilbert-space
exponents $p=q=2$ and Cauchy--Schwarz, whereas the public declaration
accepted arbitrary $p,q\geq 1$
(\texttt{w1pTime\_continuous\_in\_H}). % CLAIM: CLM-008, INC-001

\emph{Incident.}
The declaration was introduced with an explicit \texttt{sorry}, but its
general type was false. A subsequent proof attempt ended after checking
only that no capstone result used the declaration; it did not assess the
declaration's validity. The declaration remained in the public declaration set for about
one month.  The capstone theorems were unaffected because neither
depended on it, but project documentation repeated the unsupported
generalization. % CLAIM: CLM-008, INC-001

\emph{Detection.}
A pre-release statement review tested the weakest admitted exponents.
It constructed a weighted Hilbert triple and a spike sequence at
$p=q=1$ for which the stated integrability assumptions hold but no
$H$-continuous almost-everywhere representative exists.  This
counterexample showed that the problem lay in the statement rather than
in proof search. % CLAIM: CLM-008, INC-001

\emph{Response.}
The declaration was restricted to $p=q=2$, moved to an experimental
namespace, and accompanied by a statement card recording its scope.
A regression check now rejects both restoration of the unsupported
generic signature and an approved placeholder without such a card.
% CLAIM: CLM-008, INC-001

\emph{Transferable lesson.}
An explicit placeholder records the absence of a proof; it supplies no
evidence that the proposition is true.  Statement review should
therefore precede proof search and should instantiate boundary cases
whenever a declaration is more general than the argument that motivated
it.  An unused declaration still requires this review if it remains
public. % CLAIM: CLM-008, INC-001

\emph{Evidence strength.}
The counterexample, repair, and review artifacts are primary evidence.
The introduction date and the approximate one-month interval are
reconstructed from commits because the introducing session was not
identified.  The incident record accordingly assigns medium-to-high
confidence to the combined timeline. % CLAIM: CLM-008, INC-001

\paragraph{Case B: the same boundary checked before merge.}
\emph{Invariant at risk.}
A finite-dimensional identity must retain the hypotheses that keep its
arguments inside the truncated space.  A placeholder for the
antisymmetry of a box-truncated convection form omitted these
projection-invariance hypotheses
(\texttt{galerkinConvection\_antisymm}). % CLAIM: CLM-008, INC-002

\emph{Incident.}
Two proof revisions had attempted the unrestricted proposition before
leaving it as an approved placeholder. The review found that the Fourier
reindexing used by the intended proof required both arguments to belong
to the finite projection subspace, a condition absent from the proposed
signature. % CLAIM: CLM-008, INC-002

\emph{Detection.}
Independent pre-merge review identified this structural closure defect
and rejected the unrestricted proposition. A numerical test corroborated
the diagnosis: it produced a discrepancy of approximately $80.7$ without the
projection hypotheses and approximately $10^{-13}$ after imposing them.
The numerical values are corroborative observations, not a certified
exact counterexample.
% CLAIM: CLM-008, INC-002

\emph{Response.}
The declaration gained hypotheses stating that both arguments are fixed
by the finite-dimensional projection.  Under those hypotheses, the
antisymmetry proof was completed and the placeholder removed before
merge. % CLAIM: CLM-008, INC-002

\emph{Transferable lesson.}
For algebraic identities produced by truncation or projection, reviewers
should test inputs outside the intended invariant subspace.  Here that
test exposed the missing projection hypotheses, and the restricted
statement was then proved in Lean. The contrast with Case A is consistent
with the value of structural and boundary-case statement review; the two cases do not
constitute a controlled comparison.
% CLAIM: CLM-005, CLM-008, INC-001, INC-002

\emph{Evidence strength.}
The session transcript and pull-request record are primary evidence and
support the incident record's high-confidence reconstruction.  The
transcript records that two earlier revisions were unsound, although
their diffs and the numerical test were not independently re-examined
for this study.
% CLAIM: CLM-008, INC-002

\subsection{Preserving public declarations during refactoring}

\emph{Invariant at risk.}
A behavior-preserving refactor must retain every public declaration,
including declarations with no current downstream users.  Build success
alone cannot enforce this invariant because an unreferenced theorem may
disappear without breaking a dependency. % CLAIM: CLM-008, INC-004

\emph{Incident.}
A deduplication refactor replaced repeated proofs in two files with
thin instantiations of a shared module.  One public theorem was omitted
while the remaining declarations were rewired
(\texttt{edge\_inf\_eq\_schwartz\_tensor}). % CLAIM: CLM-008, INC-004

\emph{Detection.}
The merge review compared the public declarations in the proposed
version with those in the pre-refactor version.  A declaration-level
comparison found that the theorem was present in the baseline and absent
from the refactored file.  A prior structural review and the Lean build
had both passed because they checked module structure and referenced
code, respectively. % CLAIM: CLM-008, INC-004

\emph{Response.}
The missing theorem was restored as a thin wrapper around the shared
implementation.  The reviewer then repeated the comparison and
confirmed that the affected public statements matched the baseline
before merge. % CLAIM: CLM-008, INC-004

\emph{Transferable lesson.}
Refactors that promise API preservation need an explicit inventory of
public declarations.  Comparing that inventory, and the corresponding
statement text when exact preservation is intended, detects omissions
that type checking cannot observe. % CLAIM: CLM-008, INC-004

\emph{Evidence strength.}
The session transcript and pull-request record independently identify
the omitted declaration and its restoration, yielding a high-confidence
reconstruction.  Some intermediate reviewer activity survives only in
agent-message summaries, but the detection and final verification are
present in primary records. % CLAIM: CLM-008, INC-004

\subsection{Resource availability and orchestration liveness}\label{sec:inc005}

\emph{Invariant at risk.}
Each worktree should have one active owner, completed review jobs should
release their helper processes, and a build should start only when the
container has sufficient available memory.  These conditions protect
liveness in a container whose effective memory ceiling was
3.42\,GiB. % CLAIM: CLM-008, INC-005

\emph{Incident.}
Review commands from the previous night left fourteen helper-process
chains running after their worktrees were no longer active, consuming
about 1--1.5\,GiB in total.  The orchestrator incorrectly classified a
slow-responding agent as inactive and assigned a successor to the same
worktree.  The successor, unaware of the shared build-cache convention,
started a cold mathlib build.  Under the combined load, heavy Lean
builds repeatedly terminated with exit code 137 and no compiler
diagnostic. % CLAIM: CLM-008, INC-005

\emph{Detection.}
Routine monitoring had inspected the visible Lean process rather than
container-wide available memory.  An owner-requested status check showed
only 606\,MiB available.  Process working-directory inspection traced
the fourteen stale chains, and the cgroup out-of-memory counter confirmed
that the silent terminations were OOM kills. % CLAIM: CLM-008, INC-005

\emph{Response.}
Terminating the stale chains raised available memory from 606\,MiB to
2.2\,GiB.  Ownership returned to the original agent, the duplicate was
stopped, and the build succeeded under a global build lock.  Standing
rules subsequently required helper-process cleanup, a shared build
cache, serialized heavy builds, and an available-memory check before
compilation. % CLAIM: CLM-008, INC-005

\emph{Transferable lesson.}
Agent orchestration must account for the complete process tree, not only
the foreground prover or compiler.  Cause-specific cleanup should be
paired with symptom-based monitoring of available memory: later that
day, the same threshold detected a memory peak from a single active build with no
stale chains and no new OOM event. An earlier, similar failure in another
campaign had been documented but not encoded in this campaign's dispatch
rules. Placing resource checks in the harness made
them standing requirements. % CLAIM: CLM-008, INC-005

\emph{Evidence strength.}
Command output in the primary session transcript supports the process
counts, memory measurements, recovery, and same-day follow-up.  The OOM
counter was cumulative from container start, so it cannot date or
attribute each recorded kill.  The incident record therefore uses the
counter to identify the failure mechanism, not to claim a precise number
of kills in this cascade.  The earlier cross-project episode is
secondary evidence and is not needed for the reconstruction of this
incident. % CLAIM: CLM-008, INC-005
